# `seo/` — SEO tooling home (non-skill)

Everything SEO-related that is **not** an Agent Skill lives here. Skills stay in
[`.agents/skills/`](../.agents/skills/) (they must, for discovery).

| Path | Purpose |
|---|---|
| [`capabilities.json`](capabilities.json) | **Single source of truth**: capability ID → MCP `server` + `tool` + structured `args` + `runtime`. |
| [`resolve.py`](resolve.py) | Resolver: expands `{{cap:<id>}}` tokens, remaps legacy names, validates against live schemas, regenerates the map. |
| [`mcp_client.py`](mcp_client.py) | Minimal MCP stdio client — spawns a server and lists its tools + `inputSchema`. |
| [`tool-schemas.json`](tool-schemas.json) | Cached dump of every server's tool schemas (from `mcp_client.py`). |
| [`tool-map.md`](tool-map.md) | Human-readable mirror, generated by `resolve.py --map`. |
| [`mcp-servers/`](mcp-servers/) | Local MCP servers owned by this repo (e.g. `google-ads-planner`). |

## Why structured `args` (deterministic + validated)

Several capabilities share one tool — `run_report` backs four GA4 capabilities,
`api_request` backs every DataForSEO capability, `analytics_compare` backs three
modes. A bare `server: tool` is ambiguous. Each capability therefore carries
**structured JSON `args`** (the fixed arguments) plus a **`runtime`** list (the
arguments the agent supplies at call time). The resolver renders:

```
`analytics` → `run_report` {"dimensions": ["sessionSource", "sessionMedium"], "metrics": ["sessions"], "dimension_filter": {...}} (supply: property_id, date_ranges)
```

Because `args` is real JSON, `--validate-live` can check it against the server's
actual `inputSchema` (arg names, types, enums, required-coverage).

## Zero-touch server swap

1. Edit [`capabilities.json`](capabilities.json) — point a capability at the new `server`/`tool`/`args`.
2. Run the resolver:
   ```bash
   python3 seo/resolve.py --check          # tokens resolve + no alias drift
   python3 seo/resolve.py --validate-live  # tool + args vs the live inputSchema
   python3 seo/resolve.py --write          # rewrite the skills in place
   python3 seo/resolve.py --map            # regenerate tool-map.md
   ```
3. Reload MCP servers in the client.

No skill is hand-edited. The registry is the contract.

## Authoring skills with capability IDs

Reference a capability instead of a hard-coded tool name:

```markdown
Call {{cap:ga4.traffic_sources}} for the current vs previous period.
```

`resolve.py --write` expands the token to the capability's full call spec. Legacy
tool names under a capability's `aliases` are remapped automatically.

## Commands

| Command | Effect |
|---|---|
| `python3 seo/resolve.py --check` | Fail (exit 1) on unknown tokens, legacy tool names, expanded call specs that drift from the registry, or invalid GA4/GSC dimension/metric names |
| `python3 seo/resolve.py --validate-live` | Spawn each server; fail if a tool is missing or `args` violate the live `inputSchema` |
| `python3 seo/resolve.py --write` | Expand tokens to call specs + remap aliases across `.agents/skills/*/SKILL.md` |
| `python3 seo/resolve.py --map` | Regenerate [`tool-map.md`](tool-map.md) from the registry |
| `python3 seo/resolve.py --list` | Print every capability and its current call spec |
| `python3 seo/window.py --days N [--compare] [--as-of YYYY-MM-DD]` | Resolve a relative window to absolute `YYYY-MM-DD` dates (GSC-lag aware) — deterministic, testable |
| `python3 seo/report/build_report.py --findings F --out R` | Render findings JSON → Markdown (deterministic) |
| `python3 seo/report/validate_report.py --findings F [--report R] [--data D]` | Mechanical validation of findings/report |
| `python3 seo/orchestrate.py --skill S --days N [--compare] --out-dir D` | Seed a run dir: writes `.run_state.json` + a findings skeleton |
| `bash seo/check.sh` | Run `--check`, `--validate-live`, and the full test suite |
| `python3 seo/mcp_client.py [server]` | Dump a server's tools + schemas to [`tool-schemas.json`](tool-schemas.json) |

## Notes / limits

- The committed skills contain the **expanded** call spec (agent-ready). The
  `{{cap:<id>}}` token is the authoring form; `--write` materializes it.
- `--validate-live` catches **structural** mismatches (unknown arg, wrong type,
  bad enum, uncovered required field). It does **not** catch **semantic** errors
  (e.g. a GA4 dimension name that doesn't exist) — those schemas are loose
  (`dimensions` is just "array of strings").
- **Optional servers**: `dataforseo` is marked `"configured": false` and is not in
  `.roo/mcp.json`; `--validate-live` SKIPs it. Skills that use it degrade gracefully.
- Run `--check` and `--validate-live` in CI/pre-commit to catch drift.
- Tests: `python3 seo/tests/test_resolve.py` (also pytest-compatible) — registry integrity, arg/enum validation, camelCase-key guard, and expanded-spec drift guard.
- Server deps are pinned in [`requirements.txt`](requirements.txt); npm MCP servers are pinned in `.roo/mcp.json`.
- Determinism: resolve relative windows to absolute dates with `python3 seo/window.py --days N [--compare]` (GSC lags ~2 days; never include today) and state the resolved window + UTC timestamp in the output.
- `KeywordPlanIdeaService` is quota-throttled upstream (429 `RESOURCE_EXHAUSTED`). The planner server retries within a bounded budget (default 40s; override with `PLANNER_MAX_RETRY_SECONDS`) so it returns the real error *before* the MCP client's 60s request timeout, instead of the client timing out.

## Skill anatomy (minimum contract)

Every `.agents/skills/seo-*/SKILL.md` follows the same minimum shape, enforced by
[`tests/test_skill_docs.py`](tests/test_skill_docs.py):

`frontmatter (name/description/license/compatibility)` → mechanical-vs-analytical banner →
`Scope & Audience` → `When to Use` → `When NOT to Use` → `Requires` → `Workflow` →
`Determinism` → `Output` → `Troubleshooting` → `Files` → `Related / Delegation`.

Dense/conditional rules live in [`references/`](references/) (progressive disclosure);
thresholds stay inline in the skill (they are the core guardrail).

## Orchestrate-Analyze-Build (OAB) mapping

| Phase | Mechanism |
|---|---|
| **Orchestrate** | [`orchestrate.py`](orchestrate.py) + [`window.py`](window.py) seed the run (`.run_state.json`, findings skeleton); [`capabilities.json`](capabilities.json) fixes the calls; the agent issues them (SEO data arrives via MCP tools, not scripts) |
| **Analyze** | the LLM writes findings JSON ([`references/findings-schema.json`](references/findings-schema.json)) — no hand-edited Markdown |
| **Build** | [`report/build_report.py`](report/build_report.py) renders the Markdown |
| **Validate** | [`report/validate_report.py`](report/validate_report.py) checks the output against source data |

## Validation & CI

```bash
bash seo/check.sh     # --check + --validate-live + all tests
```
`--check` now also verifies expanded-spec drift, that each capability's
`policy.timeout_budget_s` fits inside the MCP client timeout (`MCP_CLIENT_TIMEOUT_S`, default 60s),
and that GA4/GSC dimension + metric names are valid (a curated allowlist — the live
`inputSchema` only says "array of strings", so `--validate-live` cannot catch a typo'd name).

Every skill's **Output** step mandates the pipeline: write `findings.json` → `build_report.py`
→ **mandatory** `validate_report.py`. The rendered report is never hand-edited.
